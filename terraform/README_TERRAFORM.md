# Terraform workflow and safe operations

This file documents next steps, safe apply instructions, and helpful `terraform import` commands to avoid destructive replacements when migrating existing resources.

Important notes
- IAM: This repository **does not** create IAM roles by default. `var.create_iam_resources` is `false`.
- We reused the existing `LabRole` (data.aws_iam_role.lab_role) as the Lambda execution role to avoid touching IAM.
- The current Terraform plan (run locally) shows additions for API Gateway, Lambdas and SNS topics. Some existing resources had name/tag mismatches that could force replacements; we've adjusted variable defaults and names to minimize replacements.

How to inspect the plan (already generated locally)

Run these from the `terraform` directory:

```powershell
# Initialize (only if you haven't):
terraform init

# Validate
terraform validate

# Create an execution plan and save it to a file
terraform plan -out=tfplan.out

# Inspect the plan in human-readable form
terraform show tfplan.out

# Or export JSON for programmatic parsing
terraform show -json tfplan.out > tfplan.json
```

Notes about imports
- After importing, run `terraform plan` again. Terraform will compare the real resource attributes with the configuration. You may need small config tweaks (names, tags, or `lifecycle.ignore_changes`) to avoid diffs.
- Do not import IAM roles unless you intend Terraform to manage them. We left IAM creation disabled by default.

Safe apply options

1) Apply everything (default):
   - `terraform apply tfplan.out` after reviewing plan.
   - This will create new resources and may replace/resync some existing ones if not imported.

2) Targeted apply for API/Lambdas only (safer):
   - `terraform apply -target=aws_apigatewayv2_api.http_api -target=aws_lambda_function.login -target=aws_lambda_function.get_boxes -auto-approve`
   - Use `-target` carefully; targeted applies can leave partial interdependencies. Use for cautious progressive rollout.

3) Create IAM first (if you want least-privilege roles):
   - Enable `create_iam_resources = true` (set in `terraform.tfvars`) and run `terraform plan` and `apply` to create Role+Policies.
   - Afterwards update Lambda `role` attributes to use the new role and re-run plan/apply. This will replace Lambda role attachments.
